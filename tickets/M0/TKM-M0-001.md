# TKM-M0-001 — Bootstrap monorepo, CI, ADR template

## Context

The first ticket in the [[takumi-os]] M0 build, per the
[DIP §18 implementation order](../raw/pack-archive/DEVELOPER_IMPLEMENTATION_PACK_v1.0.md#18-m0-implementation-order).
This ticket establishes the monorepo, the CI pipeline, the ADR
convention, and the wiki drift job. No service code yet — that's
TKM-M0-002 onwards.

## What this ticket delivers

- `~/work/takumi-os/` — runnable monorepo skeleton
- Root config: README, LICENSE, .gitignore, .editorconfig, .nvmrc,
  .python-version, .csharp-version, global.json,
  Directory.Build.props, Directory.Packages.props
- 6 GitHub Actions workflows: ci-frontend, ci-backend, ci-agents,
  ci-iac, security-scan, weekly-wiki-drift
- 3 issue templates (bug, feature, agent-task) + 1 PR template +
  CODEOWNERS
- 6 ADRs copied from the wiki to `docs/adr/0001-0006*.md` with
  "copied from wiki" provenance notes
- 3 wiki-drift helper scripts in `scripts/`

## What this ticket does NOT deliver (deferred to later tickets)

- Any service code (TKM-M0-005+)
- Any Terraform (TKM-M0-002+)
- Any Kustomize manifests (TKM-M0-002+)
- The first commit's `tickets/` directory (TKM-M0-001+ is itself
  in this ticket; subsequent tickets go in follow-ups)

## Approach

1. **Create repo directory** at `~/work/takumi-os`
2. **Write root config** in parallel (atomic, all at once)
3. **Write GitHub workflows** — validated YAML
4. **Write PR/issue templates and CODEOWNERS** — convention
5. **Copy 6 ADRs from `~/wiki/adr/0001-0006*.md`** — verbatim with
   provenance note
6. **Write 3 wiki-drift helper scripts** — `adr_check.py`,
   `openapi_consistency.py` (stub for M1+), `architecture_freshness.py`
7. **Initialise git** with conventional commit message
8. **Write this ticket file** in `tickets/M0/`
9. **Log completion** in `~/wiki/log.md`
